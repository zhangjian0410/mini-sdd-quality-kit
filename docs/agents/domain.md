# Domain docs

Use a single-context layout: root GLOSSARY.md and docs/adr/.

## Before exploring

Read GLOSSARY.md and ADRs relevant to the area being explored.
If absent, proceed silently without creating placeholders.
Use domain-modeling when terminology or decisions actually need resolving.

## Vocabulary

Use glossary terms in specs, tickets, code and review findings.
Check existing project usage before proposing a new term.

## Decision conflicts

Cite an existing ADR and explain the reason when proposing to reopen it.
Keep terminology and decisions consistent with docs/V0-IMPLEMENTATION.md.
